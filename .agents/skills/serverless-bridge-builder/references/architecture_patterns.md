# Architecture Patterns for Serverless Bridges

This document summarizes core architectural patterns for building zero-worker serverless integration bridges between external platforms and services.

---

## 1. Zero-Worker Async Processing via Next.js `after()`

Serverless platforms (like Vercel) terminate background microtasks once the HTTP response is sent unless using explicit primitives. In Next.js 15.1+:

```typescript
import { NextResponse, after } from "next/server";

export async function POST(req: Request) {
  // 1. Verify signatures & validate input fast
  // 2. Return immediate response (e.g. Discord ACK < 3s, or Webhook 200 OK)
  const res = NextResponse.json({ type: 5 }); // Defer ACK

  // 3. Queue asynchronous processing without a long-running worker
  after(async () => {
    try {
      await processPayloadAsync();
    } catch (err) {
      console.error("Async background error:", err);
    }
  });

  return res;
}
```

## 2. Inbound Signature Verification Before Body Parsing

Never run `req.json()` or execute handler code before verifying signatures:

- **Discord**:
  ```typescript
  import { verifyKey } from "discord-interactions";
  const signature = req.headers.get("X-Signature-Ed25519");
  const timestamp = req.headers.get("X-Signature-Timestamp");
  const rawBody = await req.text();
  const isValid = await verifyKey(rawBody, signature, timestamp, PUBLIC_KEY);
  if (!isValid) return new NextResponse("Unauthorized", { status: 401 });
  ```
- **Cron / Internal API**:
  ```typescript
  const auth = req.headers.get("authorization");
  if (auth !== `Bearer ${CRON_SECRET}`) return new NextResponse("Unauthorized", { status: 401 });
  ```

## 3. Bidirectional Loop Prevention

When bridging two systems (A <-> B), updates generated by the bridge itself will bounce back as notifications.

### Pattern: Origin Metadata Tag
1. **When writing to A from B**:
   Set a custom property on the entity (e.g. Google Drive `appProperties.source = "discord"`).
2. **When receiving notifications from A**:
   Inspect the property. If `source === "discord"`, silently discard.

---

## 4. Compound Idempotency & Rollback

Do NOT rely on file hashes or change event IDs:
- Collaborative docs (Google Docs/Sheets) don't have static MD5s.
- Metadata edits (renaming, permissions) require announcement but don't alter hashes.

### Use: `(entity_id, modified_time, direction)`
```sql
CREATE TABLE file_events (
  id BIGSERIAL PRIMARY KEY,
  file_id TEXT NOT NULL,
  modified_time TIMESTAMPTZ NOT NULL,
  direction TEXT NOT NULL,
  discord_message_id TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT timezone('utc', now()),
  CONSTRAINT uq_file_events UNIQUE (file_id, modified_time, direction)
);
```

### Rollback on Downstream Failure
If inserting into destination platform fails:
1. Delete the created `file_events` record immediately.
2. Do **not** advance the source page/sync token.
3. Allow the next cron poll or webhook retry to re-process cleanly.
